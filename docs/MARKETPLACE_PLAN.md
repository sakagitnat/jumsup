# แผนระบบ Creator Store (ครีเอเตอร์สร้าง–ขายเนื้อหา แบ่งรายได้กับ Jumsup)

> ร่างวันที่ 2026-09-03 · ยังไม่เริ่ม implement · ต้องตอบ "คำถามที่ต้องตัดสินใจ" ท้ายเอกสารก่อน

## 0. บริบทและข้อจำกัด

- นักพัฒนาคนเดียว ไม่มีต้นทุน ไม่มีทีมซัพพอร์ต ยังไม่จดบริษัท
- Infra ปัจจุบันฟรีหมด (Cloudflare Workers, Supabase free, Stripe pay-as-you-go)
- เป้าหมาย: ให้ผู้ใช้สร้างชุดคำศัพท์ / ชุดทักษะมา "ขาย" และ Jumsup ได้ส่วนแบ่ง
- หลักการเดิมของโปรเจกต์: subscription / payment / quota / XP เชื่อจากเซิร์ฟเวอร์ + webhook เท่านั้น — marketplace ต้องยึดหลักนี้

## 1. การตัดสินใจสำคัญที่สุด: v1 **ไม่โอนเงินสดให้บุคคลที่สาม**

การจ่ายเงินสดให้ครีเอเตอร์คนอื่นทำให้ Jumsup กลายเป็น "แพลตฟอร์มตัวกลาง" ซึ่งเปิดภาระที่คนเดียว/ไม่มีงบรับไม่ไหว:

| ภาระ | รายละเอียด |
|---|---|
| ภาษีหัก ณ ที่จ่าย | จ่ายค่าบริการให้คนไทย ต้องออกหนังสือรับรองการหักภาษี 3% + ยื่น ภ.ง.ด. |
| VAT | รายได้เกิน 1.8 ล้าน/ปี ต้องจดและนำส่ง VAT |
| Stripe Connect | จ่ายเงินให้บุคคลที่สามในไทยแทบทั้งหมดต้องเป็นนิติบุคคลจดทะเบียน |
| Chargeback | ผู้ซื้อ dispute → แพลตฟอร์มรับผิดชอบ ทั้งที่จ่ายส่วนแบ่งครีเอเตอร์ไปแล้ว |
| PDPA | เก็บเลขบัญชี/บัตรประชาชนครีเอเตอร์เพื่อจ่ายเงิน = ข้อมูลอ่อนไหว ต้องมีมาตรการ |
| ซัพพอร์ต | "เงินไม่เข้า" "ชุดนี้ห่วยขอเงินคืน" "ขอใบหักภาษี" — งานคนเดียวไม่ไหว |

**ทางออก v1:** Jumsup เป็น **merchant of record** (ผู้ขายอย่างเป็นทางการ) — ผู้ซื้อจ่ายเงินให้ Jumsup, ครีเอเตอร์ได้ **ค่าตอบแทนที่ไม่ใช่เงินสด**:

1. **เวลา Pro** — ส่วนแบ่งแปลงเป็นวัน Pro อัตโนมัติ (เช่น รายได้ครีเอเตอร์ 100 บาท = Pro 30 วัน)
2. **Gift code** — ครีเอเตอร์กดแลกยอดเป็นโค้ด Pro เอาไปแจกผู้ติดตามตัวเอง (ช่วยครีเอเตอร์โตด้วย) — ต่อยอดระบบ gift code ที่มีอยู่แล้ว
3. **ยอดสะสมเป็นเงินบาท (ledger)** — โชว์ในหน้าครีเอเตอร์ว่า "สะสมแล้ว X บาท" พร้อมข้อความชัดเจนว่า *การถอนเป็นเงินสดจะเปิดในอนาคตเมื่อ Jumsup จดทะเบียนบริษัท* — ยอดนี้ผูกกับตัวตนไว้ ถอนได้ทีหลังจริง

ข้อดี: ไม่มีภาระภาษี/บัญชี/ถอนเงิน/KYC เลย · chargeback แค่เพิกถอนสิทธิ์ผู้ซื้อ + ปรับ ledger (ยอดยังไม่ออกไปไหน) · ครีเอเตอร์ได้คุณค่าจริง (Pro มีมูลค่า) · plumbing ที่สร้างใช้ต่อได้ตอนเปิดเงินสด

**Phase 3 (เมื่อมีรายได้พอ):** จดบริษัท (~1–1.5 หมื่นบาท) → ปรึกษานักบัญชี → เปิด Stripe Connect Express + payout เงินสด + หัก ณ ที่จ่าย ตามกฎหมาย

## 2. งานที่ต้องเสร็จ "ก่อน" เปิดขาย (pre-work)

ระบบพวกนี้ปัจจุบันออกแบบมาสำหรับเนื้อหาฟรี ต้องแก้ก่อนมีเงินเข้ามาเกี่ยว:

### 2.1 XP กับเนื้อหาเสียเงิน (สำคัญสุด)
`award_flashcard_xp` ให้ +10 ต่อคำทุก deck ถ้าซื้อชุด 500 คำ = +5,000 XP ทันที และครีเอเตอร์ปั๊ม XP ตัวเองได้
- **แก้:** XP จากชุดที่ "ซื้อมา / import มา" คิดแบบลดทอน (เช่น เพดาน 100 XP ต่อชุดที่ไม่ได้สร้างเอง) หรือให้ XP เฉพาะคำที่ผ่าน SRS จริง ไม่ใช่แค่กดผ่าน
- ครีเอเตอร์ทำ/เล่นชุดตัวเอง: ไม่ได้ XP ลีดเดอร์บอร์ด

### 2.2 กัน plagiarism ตอน publish
คนเอาชุดฟรีของคนอื่น (หรือของ Jumsup Official) มาตั้งราคาขาย
- **แก้:** ตอน publish ชุดเสียเงิน คำนวณ fingerprint (hash ของคำ+ความหมายที่ normalize แล้ว, หรือ shingle similarity) เทียบกับชุดสาธารณะที่มีอยู่ ถ้าใกล้เกินเกณฑ์ → เข้าคิวแอดมินตรวจก่อน ไม่ให้ขึ้นขายอัตโนมัติ

### 2.3 Moderation เนื้อหาเสียเงิน
- ชุดเสียเงินทุกชุด **ต้องผ่านแอดมินอนุมัติ** ก่อนขึ้นขาย (ไม่ใช่ publish แล้วขายเลย)
- ต่อยอดหน้า "เนื้อหา" ในแอดมินที่มีอยู่: เพิ่มสถานะ `pending_paid_review` / `approved_for_sale` / `rejected`
- ครีเอเตอร์แก้เนื้อหาชุดที่ขายอยู่ → กลับเข้าคิวตรวจ (กัน bait-and-switch)

### 2.4 Refund ของเนื้อหา
ระบบ refund ปัจจุบันผูกกับ subscription เท่านั้น
- นโยบาย: คืนเงินได้ภายใน N วัน ถ้ายังเรียนไม่เกิน X% ของชุด
- คืนเงิน → เพิกถอน `entitlement` + ปรับ ledger ครีเอเตอร์ลง + log
- ต่อยอด `refund_requests` เดิม เพิ่ม `kind='content'` + `content_id`

### 2.5 self-dealing / บัญชีปลอมปั่นยอด
ต่อยอดหน้า "ตรวจ XP" ที่เพิ่งทำ (migration 028) ให้ตรวจ:
- ครีเอเตอร์ซื้อชุดตัวเอง (ทางตรง/ผ่านบัญชีที่จ่ายด้วยบัตรใบเดียวกัน)
- บัญชีใหม่จำนวนมากซื้อชุดครีเอเตอร์คนเดียวในเวลาใกล้กัน

## 3. โมเดลข้อมูล

### ใช้ของเดิม
- **`entitlements`** — เพิ่มแถว `entitlement='content'`, `source='purchase'`, `source_ref=<set_id>`, `metadata={type:'vocab'|'skill', order_id, price_thb}` · unique constraint เดิมกัน insert ซ้ำได้เลย
- **`gift_codes`** — ครีเอเตอร์แลกยอดเป็นโค้ด
- **`refund_requests`** — เพิ่ม path เนื้อหา
- **`processed_webhook_events`** — idempotency มีอยู่แล้ว

### ตารางใหม่ (สมมติ migration `029_creator_store.sql`)
```
content_listings
  content_id text pk        -- อ้าง vocab_sets.id / practice_sets.id
  content_type text          -- 'vocab' | 'skill'
  creator_user_id uuid
  price_thb integer          -- 0 = ฟรี (ปิดการขาย)
  status text                -- 'draft'|'pending_review'|'approved'|'rejected'|'unlisted'
  platform_pct integer       -- ส่วนแบ่ง Jumsup ตอนขาย (snapshot ไว้กันเปลี่ยนย้อนหลัง)
  fingerprint text           -- กัน plagiarism
  approved_at, rejected_reason, created_at, updated_at

content_orders
  id uuid pk
  buyer_user_id uuid
  content_id text
  price_thb integer
  platform_cut_thb integer
  creator_earn_thb integer
  stripe_session_id text unique
  stripe_payment_intent text
  status text                -- 'pending'|'paid'|'refunded'
  created_at, paid_at, refunded_at

creator_ledger              -- บันทึกรายการเปลี่ยนยอด (append-only)
  id uuid pk
  creator_user_id uuid
  delta_thb integer          -- + ขายได้, - refund, - แลก Pro/gift
  reason text                -- 'sale'|'refund'|'redeem_pro'|'redeem_giftcode'|'adjust'
  ref_order_id uuid null
  created_at
  -- ยอดคงเหลือ = sum(delta_thb)

creator_payouts            -- Phase 3 เท่านั้น (เงินสด) — ยังไม่สร้างก็ได้
```

### RPC ใหม่ (security definer)
- `has_content_access(p_type, p_id)` → creator OR มี entitlement OR (ตัวเลือก) Pro-เข้าถึงทุกชุด
- `record_content_sale(order...)` — เรียกจาก webhook: สร้าง entitlement + order + ledger +sale ในทรานแซกชันเดียว, idempotent ด้วย stripe_session_id
- `refund_content_order(order_id)` — เพิกถอน entitlement + ledger -creator_earn + order.status
- `creator_redeem(amount, as: 'pro'|'giftcode')` — ตัด ledger, เพิ่ม pro_bonus_until / สร้าง gift_code
- `creator_dashboard()` — ยอดคงเหลือ, ยอดขายรวม, ชุดที่ขายดี, รายการ ledger ล่าสุด

## 4. แผนส่งงานเป็นเฟส

### เฟส 0 — pre-work (จำเป็น ~1 สัปดาห์)
ข้อ 2.1–2.5 ข้างบน · migration สำหรับ XP cap เนื้อหา import + fingerprint helper

### เฟส 1 — ขายได้ + ครีเอเตอร์เห็นยอด (ยังไม่แลก ~1.5 สัปดาห์)
- migration `029_creator_store.sql` (ตาราง + RPC)
- หน้าครีเอเตอร์ในเว็บหลัก: ตั้งราคาชุด → ส่งเข้าคิวตรวจ
- แอดมิน: หน้า "ร้านค้าครีเอเตอร์" — อนุมัติ/ปฏิเสธชุด, ดูยอดขายรวม, ดู ledger รวมทั้งระบบ, ปรับ `platform_pct` (ค่าเริ่ม 30%)
- Community browse: โชว์ราคา + ปุ่ม "ซื้อ" (ปุ่ม import เดิมเช็ก `has_content_access` ก่อน)
- Stripe Checkout `mode:payment` (จ่ายครั้งเดียว) + webhook `checkout.session.completed` → `record_content_sale`
- หน้าครีเอเตอร์: ยอดสะสม (บาท) + ยอดขายต่อชุด + ข้อความ "ถอนเงินสดเปิดภายหลัง"

### เฟส 2 — แลกยอด + refund (~1 สัปดาห์)
- ครีเอเตอร์แลกยอด → Pro-days / gift code
- ผู้ซื้อขอคืนเงินเนื้อหา → คิวแอดมิน → `refund_content_order`
- ตรวจ self-dealing ในหน้า "ตรวจ XP"
- นโยบาย: หน้า Refund/ToS อัปเดต (ดูข้อ 5)

### เฟส 3 — เงินสดจริง (เลื่อนไปก่อน — ต้องจดบริษัท)
- Stripe Connect Express onboarding
- `creator_payouts` + payout รายเดือน ขั้นต่ำ (เช่น 500 บาท)
- หัก ณ ที่จ่าย + เอกสารภาษี + นักบัญชี
- **เงื่อนไขเริ่ม:** มีรายได้ marketplace สะสม > เกณฑ์ที่คุ้มค่าจดบริษัท

## 5. เช็กลิสต์นโยบาย/กฎหมาย (ทำแม้เป็นแบบไม่จ่ายเงินสด)

- [ ] **ToS ครีเอเตอร์**: ครีเอเตอร์รับรองว่าเนื้อหาเป็นของตัวเอง ไม่ละเมิดลิขสิทธิ์/ข้อสอบจริง · Jumsup เป็นผู้ขาย · ค่าตอบแทน v1 เป็น Pro/โค้ด · Jumsup ถอดชุดได้ทุกเมื่อ
- [ ] **ToS ผู้ซื้อ**: ซื้อแล้วเข้าถึงในบัญชีตัวเอง ห้ามแจกจ่ายต่อ · เงื่อนไขคืนเงิน
- [ ] **นโยบายคืนเงินเนื้อหา** เขียนชัด (กี่วัน, เงื่อนไข %)
- [ ] **ความเป็นส่วนตัว**: v1 ไม่เก็บข้อมูลการเงินครีเอเตอร์เลย — ระบุใน privacy ว่าจะเก็บเมื่อเปิด payout
- [ ] ราคาแสดงรวม/ไม่รวมอะไร (v1 ไม่มี VAT เพราะยังไม่ถึงเกณฑ์/ไม่จด)
- [ ] เก็บหลักฐานการขาย (order + timestamp) ไว้ ≥ 5 ปี เผื่อภาษีบุคคลของตัวเอง (รายได้ Jumsup ส่วนแบ่ง = เงินได้ของคุณ ต้องยื่นภาษีบุคคลอยู่แล้ว)

## 6. ความเสี่ยงที่เหลือ + การรับมือ

| ความเสี่ยง | รับมือ |
|---|---|
| Stripe fee (~3.65% + 11฿ ในไทย) กินกำไรชุดราคาถูก | ราคาขั้นต่ำ ~19–29 บาท · หรือขายเป็นแพ็ก |
| ครีเอเตอร์ทิ้งชุดคุณภาพต่ำจำนวนมาก | ต้องผ่านรีวิว + จำกัดจำนวนชุดค้างรีวิว/คน |
| ผู้ซื้อรู้สึกโดนหลอกเพราะพรีวิวน้อย | บังคับพรีวิว ≥ X รายการ/ตัวอย่างบทอ่าน ก่อนซื้อ (มี `loadCommunityPreview` อยู่แล้ว) |
| Dispute/chargeback | v1 ยอดครีเอเตอร์ยังไม่ออก → แค่ปรับ ledger · ตอบ dispute ด้วยหลักฐาน order |
| ภาระซัพพอร์ตโต | จำกัด scope: ไม่มีแชท ไม่มีคำขอพิเศษ · FAQ ชัด · refund เป็นฟอร์ม |

## 7. คำถามที่ต้องตัดสินใจก่อนเริ่ม

1. **โมเดลราคา**: ซื้อขาดต่อชุด / แพ็กหลายชุด / "Pro เข้าถึงทุกชุด" แล้วแบ่งรายได้ตามยอดเล่น — อันไหน? (กระทบสถาปัตยกรรมทั้งหมด — แนะนำ **ซื้อขาดต่อชุด** สำหรับ v1 เพราะง่ายสุด)
2. **ส่วนแบ่ง Jumsup**: กี่ % (แนะนำ 30% ช่วงแรก ปรับได้ในแอดมิน)
3. **ค่าตอบแทน v1**: ยืนยันว่ารับได้กับ "Pro-days + gift code + ledger ที่ยังไม่ถอนเงินสด" ใช่ไหม
4. **ราคาขั้นต่ำ/สูงสุด** ต่อชุด
5. **Pro รวมเนื้อหาเสียเงินไหม** (ถ้ารวม ครีเอเตอร์ควรได้ส่วนแบ่งจาก pool แยก — เพิ่มความซับซ้อน แนะนำ v1 ไม่รวม)
6. เปิดขายเฉพาะชุดคำศัพท์ก่อน หรือชุดทักษะด้วยเลย
